### How to work
- Go wave by wave. Within a wave, items that touch different files can run in parallel (one
  agent per file group); never let two agents edit the same file at once.
- One item = one focused change plus its regression test. Don't refactor beyond what the item
  says. If a fix turns out wrong or risky once you're in the code, skip it and write down why —
  don't force it.
- Line numbers are from 0.4.20 and drift as earlier items land: find code by function name.
- Items marked **Confirm first** begin with the test that proves the bug. If it doesn't
  reproduce, drop the item and say so.
- Record as you go, the way this repo does:
  - `CHANGELOG.md`: an entry under `## Unreleased` for every user-visible change (plain
    sentences saying what the user now sees, like the existing entries).
  - `docs/decisions.md`: a numbered decision when behavior or a design rule changes — what was
    found (with the counts/evidence), what changed and why there, what was measured and left
    alone, what is deliberately not done. Group related items into one decision.
  - Don't commit unless the user asks. Don't bump the version or run `scripts/release.sh`
    unless asked (`RELEASING.md`). Stage files by name; strays like `out/` accumulate.

### Hard constraints (from `AGENTS.md` — breaking one is a bug even if the tests pass)
1. **Prompt cache.** The system prompt and the tool list (names, order, descriptions, schemas)
   are fixed for a session. Never add, remove or reorder tools or change a description while a
   session runs; block behavior when a tool runs instead (see plan mode in `plan.rs`/`agent.rs`).
2. **History is append-only and stored exactly as sent.** Notes to the model go at the end as
   user messages in `<system-reminder>` tags. Only compaction and `/reload` rewrite history.
3. **Adapters** in `llm/` convert the OpenAI-format history the same way every time, so the
   bytes of earlier messages never change.
4. **Token budget.** System prompt + tools stay under ~3k tokens:
   `main::tests::system_prompt_and_tools_fit_the_token_budget` must pass. Keep tool
   descriptions short.
5. Rules that must always hold go **in code**, not only in `prompt/system.md` (users can
   replace that text with `[prompt] system`).
6. Match the surrounding code: doc comments on public items and anything non-obvious, no
   comments that narrate changes, tests in the touched module's existing
   `#[cfg(test)] mod tests`, **no network in tests**.
7. **One current-thread Tokio runtime** runs everything (UI, agent, subagents, IPC): don't add
   blocking work to it; use `spawn_blocking`, async processes, and timeouts.

### Deliberate trade-offs — don't change these (each is argued in `docs/decisions.md`)
- No approval prompts; `bash` runs anything; `/undo` is the safety net (decision 6).
- Inline renderer by default outside Kil; fullscreen only for `TERM_PROGRAM=kil` (16).
- Esc discards queued messages (37). No LSP (30). The model's `| tail` on waits (34, 37).
- The status line's three hues and the palette derivation (16, 38).
- No rustfmt adoption (the long-line style is deliberate). Keep `dom_smoothie` (~1.1 MB) and
  reqwest `http2` (~0.5 MB) — measured, worth it. Update signing is deferred (key custody
  outweighs the value for a personal tool).

### Verification recipe
- After every item: `cargo clippy --workspace --all-targets --locked -- -D warnings` and
  `cargo test --workspace --locked`. Baseline at 0.4.20: clippy clean, **338 passed**, ~4 s.
- Any change under `tui/` (or text the TUI draws): `cargo build`, then
  `scripts/frames.py out/<name> --killi target/debug/killi --sizes 80x24 60x24 --themes night paper --scenes <relevant>`
  and the same with `--inline`. It needs `pyte` — make a venv
  (`python3 -m venv /tmp/frames-venv && /tmp/frames-venv/bin/pip install pyte`) and run the
  script with that Python; `--png` also needs Google Chrome. A layout counts as checked only
  once drawn at 80x24 **and** 60 columns. Delete `out/` afterwards.
- Changes to `live.rs` or to code that answers other sessions:
  `scripts/live_check.py --killi target/debug/killi` (29 checks, ~35 s).
- **Never run killi against the real HOME** (`~/.killi`): a pty closing during the first-run
  guide writes into it and can orphan a process. `frames.py`/`live_check.py` already use a
  scratch HOME; do the same for any manual run. Never call real model providers.

## 3. Root-cause groups (fix the cause once)

1. **Typed provider errors** (W1-A1). `Client::complete` turns `Failure{status,retryable,…}` into a string, and three word lists then re-classify it: `is_overflow`, `error_hint` and the ChatGPT advice. Covers V5, the 401-hint misfires, and the overflow-reads-as-auth hint. W1-A2 and W1-A3 add their failure kinds on the same seam.
2. **One sanitize-for-terminal seam** (W1-D2, W1-D3). Untrusted text (model text, tool summaries and outputs, todos, questions, swarm items, provider error bodies) must be cleaned once, where it enters the TUI. Covers the escape, tab and newline bugs, and `gist` used everywhere for errors.
3. **One "end of an assistant message" point in the TUI** (W1-D5, W1-D6, W1-D7). `flush_partial` resets Markdown state and is called on Retry and Notice as well. Covers V2, V3, and notices glued onto replies.
4. **Session ownership** (W1-E1). Hold an exclusive lock on the log the session writes, like `live.rs` presence. `-c`, `-r`, `/resume` and `/prune` honor it.
5. **One config-edit + atomic-write helper** (W1-F1). Use one table-span rule (comments, spaces, multi-line strings) and re-parse before writing. Write via temp + fsync + rename, keeping the file mode. Reuse it for `last-model.json`, `mcp-off.json` and `later.md` (chatgpt.rs already does this).
6. **Conversation reset in one place** (W2-C2). `/new` and `/resume` share one `reset_conversation()`: queue, todos, totals, peer notes, snapshots.
7. **Mutable per-session state behind an immutable `Rc`** (W1-B6, W2-C3). Covers `Context.images` (V1) and `Settings.search` going stale on `/new`, `/reload` and `/resume`.

### Wave 1: crashes, wedged sessions, data loss, broken screens (P0/P1)

#### W1-A1 · P1 · risk 12 · Typed provider errors (root cause of V5 and of wrong error hints)
- **Files:** `llm/mod.rs` (`Failure`, `complete` :156-158, `classify` :320-333), `agent.rs:1666-1671` (`is_overflow`), `tui/mod.rs:3281-3299` (`error_hint`), `login/chatgpt.rs:210-217`.
- **Problem:** `complete` returns `anyhow!("{message} (after N attempt(s))")`, and callers re-classify by substring:
  - "too many tokens" (Bedrock's throttle text) → overflow → needless compaction;
  - "401" anywhere, e.g. "4010" or "214013 tokens" → "Check api_key".
- **Evidence:** tested (D §P2, A §P2 error_hint, B §P2); V5 traced.
- **Fix:**
  - Add `pub struct ProviderError { status: Option<u16>, kind: ErrorKind, message: String, attempts: u32 }` with `ErrorKind = Overflow | Auth | Quota | RateLimited | Media | Transport | BadResponse | Other`. Classify it once in `classify` and the parsers' mid-stream error paths, and return it as `anyhow::Error::new(ProviderError)` so the Display text stays the same.
  - `is_overflow` downcasts and checks `kind == Overflow`: status 400/413/422 with an overflow phrase, never 429 or 5xx.
  - `error_hint` keys on `kind`/`status`, never on digits in text. Use `tools::count` for "attempt(s)".
- **Test:** `llm::tests::throttle_text_is_not_overflow` (429 + "Too many tokens, please wait" → RateLimited); `tui::tests::hint_follows_status_not_digits` ("prompt is too long: 214013 tokens" → no api_key hint).
- **Verify:** clippy, `cargo test`.
- **Effort:** M · **Regression risk:** Med (every error path); keep the message text unchanged.

#### W1-A2 · P1 · risk 12 · Transport errors keep their cause; unfixable ones aren't retried
- **Files:** `llm/mod.rs:184,212`; same formatting at `login/chatgpt.rs:185-187` and `tools/web.rs:496-526`.
- **Problem:** reqwest's `Display` drops the source. DNS failure, connection refused, TLS rejection and idle timeout all read "error sending request for url (…)". All of them are retried 10× (2–7 min).
- **Evidence:** tested (F §P2, J §P1).
- **Fix:**
  - Format with the full source chain (walk `std::error::Error::source()`).
  - Fatal (no retry): builder/URL errors and TLS certificate errors.
  - Connect/DNS errors: at most 3 attempts.
  - Stream-decode and timeout errors: transient as today. Put the kind into `ProviderError` (W1-A1).
- **Test:** a local listener that closes at once and a bad host → message contains the cause, attempts ≤ 3.
- **Effort:** S–M · **Depends on:** W1-A1.

#### W1-A3 · P2 · risk 9 · [V7] A 200 that isn't an event stream fails at once and shows its body
- **Files:** `llm/mod.rs:203-228`.
- **Problem:** an HTML or JSON body from a misconfigured `base_url` or gateway: its lines are skipped as non-`data:`, it fails as "empty response …", is retried for 142 s, and the body is never shown (all three protocols).
- **Evidence:** tested (F §P2-5).
- **Fix:** if the `content-type` is present and isn't `text/event-stream`, or the body ends with no `data:` line, fail with `kind: BadResponse` (not retryable). Include the status, content-type and the first ~500 chars of the body, tags stripped if HTML.
- **Test:** local server returning `200 text/html <html>…` → one attempt, error contains the excerpt.
- **Effort:** S.

#### W1-A4 · P1 · risk 10 · Responses `/effort off` replays reasoning items without `encrypted_content`
- **Files:** `llm/responses.rs:43-45, 59-63, 137`.
- **Problem:** with thinking off, `include: ["reasoning.encrypted_content"]` isn't sent, yet reasoning items (summary only) are stored and replayed under `store:false`. OpenAI should reject every later request, `/compact` included.
- **Evidence:** traced (F §P1); not run live.
- **Confirm first:** a unit test on `prepare` with thinking off that shows a replayed reasoning item lacking `encrypted_content`.
- **Fix:** when converting history, skip reasoning items that have neither `encrypted_content` nor (for gateways) summary text. Skipping is deterministic, so it's cache-safe. Consider always sending `include` when the model reasons by default.
- **Test:** `responses::tests::reasoning_without_encrypted_content_is_not_replayed`.
- **Effort:** S.

#### W1-A5 · P2 · risk 8 · OpenAI streamed tool-call `index` is trusted
- **Files:** `llm/openai.rs:168-173`.
- **Problem:** a gap in indices creates nameless calls that are replayed with `name:""` forever (rejected by both APIs). Index `u64::MAX` → `resize_with` panic → abort.
- **Evidence:** tested (F §P2).
- **Fix:** map provider indices through a small `index → slot` map (append order), cap the number of calls (e.g. 128), and drop calls with an empty name at `finish` with a parse error the model sees.
- **Test:** indices `[0, 5]` → two calls, no empty names; index `u64::MAX` → no panic.
- **Effort:** S.

#### W1-A6 · P2 · risk 9 · Concurrent subagents share one 429 cooldown
- **Files:** `llm/mod.rs:149-164` (`Client`, shared via `Rc` by subagents, `agent.rs:1224`).
- **Problem:** each swarm member backs off alone. On capped providers six members each burned 139–152 s on 10 attempts and failed.
- **Evidence:** session logs (F §P2).
- **Fix:** add `cooldown: Rc<Cell<Option<Instant>>>` to `Client`. A 429 sets it to now + wait, and every attempt first sleeps until it passes. Count attempts that waited on another member's cooldown separately, so they don't burn the 10.
- **Test:** two concurrent completes against a local server returning 429 once → the second waits; total attempts bounded.
- **Effort:** M.

#### W1-B6 · P1 · risk 9 · [V1] `Context.images` follows `/model`
- **Files:** `tools/mod.rs:39,51` (`images: bool` → `Cell<bool>`), `agent.rs:389, 426, 467-471` (delete `ctx_images`; `switch_model` sets the cell), readers in `tools/files.rs:97`, `tools/web.rs:331`, `agent.rs:956-957`.
- **Problem:** `Rc::get_mut` is always `None` (the `Aside` holds a `Weak`), so image reading follows the start model.
- **Fix:** use the same pattern as `search: RefCell<…>`.
- **Test:** `agent::tests::switching_model_updates_image_capability` (idle agent, switch to a text-only client, `read` an image → error).
- **Effort:** S.

#### W1-B1 · P0 · risk 20 · A rejected image must not wedge the session
- **Files:** `agent.rs:566-573` (`run`'s error arm), `tools/files.rs:83-134` (`read_image`, `image_url`), `llm/{openai,anthropic,responses}.rs` (`prepare`), `mcp.rs:295-300`.
- **Problem:** if the provider rejects an image, the image stays in history and every later request fails with the same 400, `/compact` included. Triggers:
  - a `.png` that is a Git LFS pointer;
  - a mislabeled or oversized image;
  - `/model` to a text-only model while images are in history.

  Decision 26's "strip older media on rejection" only exists inside reduced compaction.
- **Evidence:** tested (G §P0), reproduced with a simulated rejection (I §P1), V1.
- **Fix (three layers):**
  1. **Prevent:** `read_image` and the paste/drop path check the magic bytes (PNG `\x89PNG`, JPEG `FF D8 FF`, GIF `GIF8`, WebP `RIFF….WEBP`) against the extension, and refuse with a clear error (an LFS pointer says so).
  2. **Text-only model:** each adapter's conversion replaces `image_url` parts with a text part `[image omitted: this model can't see images]` when `!model.images`. It is deterministic per model, so it's cache-safe (a model switch restarts the cache anyway).
  3. **Unexpected rejection** (`ErrorKind::Media` from W1-A1: 400 naming image or media): do one recovery rewrite that replaces every image part with that placeholder. Record it as a `compaction` entry with `cause: {"media_rejected": …}`, emit a notice, and retry once. This is a history rewrite, allowed only as a compaction-kind record. Say so in decisions.md. The trade-off is one uncached request.
- **Test:** `agent::tests::a_rejected_image_is_stripped_once_and_the_turn_goes_on` (fake client: first call 400 "image", second ok → history has the placeholder, log has a compaction record).
- **Effort:** L · **Depends on:** W1-A1, W1-B6 · **Regression risk:** Med (keep the rewrite record-compatible with `session::load`).

#### W1-B2 · P1 · risk 12 · [V8] Resumed sessions can start subagents
- **Files:** `session.rs:69-79` (`Session::child`), `agent.rs:412, 1214-1215`.
- **Problem:** `children` restarts at 0 on resume, and `child(n)` opens `agent-N.jsonl` with `create_new`, so the first N children fail with "Could not start the subagent".
- **Fix:** `Session::child` loops to the next free `agent-N.jsonl` on `AlreadyExists` and returns the n it used. The agent stores it back into `children`.
- **Test:** `session::tests::child_logs_skip_existing_names`.
- **Effort:** S.

#### W1-B3 · P1 · risk 16 · No second cut of tool results that fit the tools' own budget
- **Files:** `agent.rs:28` (`MAX_RESULT_CHARS = 50_000`), `:1000-1002`, `:1356-1367` (`shorten`); `tools/mod.rs:19` (51,200-byte budget), `files.rs:58-63`, `bash.rs:599-624`, `web.rs:202-206`, `search.rs:168`, `swarm.rs:83-84`.
- **Problem:** tools cap at 51,200 bytes, but the agent cuts anything over 50,000 to about 5 KB, so `read`'s exact "continue at offset N" hint then skips the missing lines. This hit 27 results in 20 of 175 real sessions.
- **Evidence:** tested (I §P1); caps disagree (G §P3).
- **Fix:** make `MAX_RESULT_CHARS` a backstop above the tools' budget, e.g. `tools::MAX_OUTPUT_BYTES + 8_192`, compared in bytes. Results the tools already bounded pass untouched. MCP, hooks and swarm text still get `shorten`'s spill.
- **Test:** a 51,000-byte `read` result reaches history whole.
- **Effort:** S.

#### W1-B4 · P1 · risk 12 · Compaction can't storm
- **Files:** `agent.rs:693-718` (`compaction_due`/`compaction_pressure`), `:655-661`, `:1216-1252` (`subagent`), `:425-431` (`switch_model`).
- **Problem:**
  - (a) No progress check: when the system prompt + kept requests already exceed the limit, it compacts before every step (tested: 8 requests for a 4-step run, 4 of them summaries).
  - (b) A fork starts with `stats.context = 0` and `accounted_messages = 0`, so it estimates the inherited history at about 2× and compacts on step 1.

## 9. Known gaps (the audit was cut short)

### 9.1 Security: what the stopped security audit never examined
Already in the plan from other audits: escapes (W1-D2), plan mode (W2-B3), `killi tell` framing (W3-A1), broker uid (W3-A2), OpenCode Go hosts (W3-A3), key in `Debug` (W3-A4), project eager MCP (W3-A5), `notify` (W3-A6), update chain (W5-B2), log and snapshot file modes (W2-E1e), the secret answer in ↑ history (W2-D3n), hooks failing open (W2-B4). Not examined:

1. **Reminder impersonation. Found while checking these gaps; traced, so do it as W3-A7, P1, first in Wave 3.**
   - **The hole:** `@file` contents are put inside `<system-reminder>…<file …>` without escaping (`tui/mention.rs:67-69`). `prompt/system.md:20` tells the model that reminder text comes from killi. So a file in a cloned repo containing `</file></system-reminder>` followed by instructions gets killi's authority when the user names it with `@`. The same applies to any `read` result, web page, MCP result or peer message that contains a literal `<system-reminder>` tag.
   - **Fix:** where untrusted text enters history (`mention::expand`, tool results in `finish_call`, peer notes), neutralize `<system-reminder>`/`</system-reminder>` (and `</file>` inside file blocks), e.g. by escaping `<` to `&lt;` in those tags. This is deterministic and append-only, so it is cache-safe.
   - **Test:** an `@file` holding `</file></system-reminder>x` yields exactly one reminder block.
2. **What a project config can set.** `config.rs:88` says only `[mcp]` eager comes from a project's `.killi/config.toml`. Confirm that nothing else is read from a project (providers or `base_url`, `[search] url`, hooks, `[prompt]`). Any of those would let a cloned repo redirect keys or run commands.
3. **Hook output.** It is appended as `<system-reminder>A hook says: …` (`agent.rs:946`), so a hook that echoes file content passes that content on with killi's authority. Low risk: hooks are the user's own.
4. **Predictable temp paths.** Names like `killi-shot-<pid>-<nanos>.png`, spill files and sockets weren't checked for symlink or race attacks. macOS `$TMPDIR` is per-user and 0700, so the risk is likely low.
5. **ChatGPT sign-in.** The state is random and checked, and the wait is bounded (`login/chatgpt.rs:270, 372, 442`). Not checked: that the callback binds to 127.0.0.1 only, that a code can be used only once, and what a second concurrent sign-in does.
6. **Secrets in what's recorded.**
   - Session logs keep pasted keys and tool output verbatim. That's inherent, which makes W2-E1e's 0600 mode matter.
   - Not checked: the mode of spill files, and whether provider error bodies echo the key into the log and onto the screen (some gateways do).
7. **`fetch_url` and Chrome.** The sandbox stays on (no `--no-sandbox`, `tools/web.rs:230`). Not checked: redirects to `file://` or to the local network.
8. **`killi ask`.** Any process running as the same user can make another session's model answer from its conversation, secrets included. The note asks for no secrets; nothing enforces it.
