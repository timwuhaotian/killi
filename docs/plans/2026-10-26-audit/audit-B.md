- **[tui/mod.rs:1920, tools/mod.rs:136, tui/history.rs:47-60, tui/text.rs:313, tui/mod.rs:2554-2565]** A line break inside any model-supplied field garbles the screen in both renderers; the common case is a multi-line `ask_user_question`.
  Scenario: the model asks `"Which approach should I take?\nA keeps the API.\nB is faster."` (models routinely write questions this way; `question_args`, agent.rs:1617, only trims). The question is emitted as `Line::Words`; `history::clean` keeps `\n`, and `wrap_words` treats `\n` as a zero-width character inside a word, so the row carries a raw LF. With raw mode's OPOST off, LF moves down without a carriage return: the question renders as a staircase, and after the answer the `↳ B` row overwrites "A keeps the API.", "B is faster." floats mid-screen, and the tool row (`tools::summary` keeps the whole question for `ask_user_question`) staircases again. The same path is open for a typed multi-line answer (its `brief`, agent.rs:1063), `todo.content`, paths/URLs/queries in summaries, swarm descriptions, and every inline `commit()` (notices, errors), which is written raw.
  Impact: the user can't read the question they're answering and the transcript stays corrupted; the most interactive moment of a session looks broken.
  Verified: reproduced — `B/shots/qnl-80x24-full-asking.png`, `B/shots/qnl-80x24-full-answered.png`, `B/shots/qnl-80x24-inline-answered.{png,txt}`, `B/shots/escq-80x24-full.png`.
