Killi

A quiet harness for long-running agents.

Brand book

Killi is a coding agent for the terminal. The interface is a conversation printed into the terminal's own scrollback, with a small live area redrawn at the bottom: what is running now, the task list, the prompt and a status line. It is set in one monospace style, on the terminal's own ground, with two colors that each mean one thing. Use this file as the rule book when you render anything that is Killi — the TUI itself (crates/killi/src/tui), the docs, a screenshot. Where the TUI and this file disagree, one of them has a bug.

Principles

  1. Quiet by default. The ground is the terminal's, the text is fg, and most lines carry no color at all. Color is spent only where something is live or waiting.
  2. Two colors, two meanings. lagoon is Killi — the caret, running and finished work, the active mode, commands. fin is the human — your messages, questions waiting on you, your answers. Never swap them; never use both on one element. The status line alone adds a hue per kind of figure (effort, tokens, branch) and they mean nothing else.
  3. The grid is the layout. Everything aligns to character cells and rows. A status glyph sits in column 0 and its text in column 2; output hangs off a │ gutter in column 2. Separate with blank rows, never with boxes.
  4. Compact and durable. One row per tool call, long output behind Ctrl+O, never two blank rows in a row. Every state has a glyph and a word, not just a color, so it still reads with NO_COLOR.

Voice

  • Lowercase commands and flags: killi -c, /compact. Sentence case for everything Killi says. No exclamation marks.
  • Terse and present tense: Plan mode off., Nothing to expand yet. Never "I will now…", never "Successfully".
  • Numbers carry their unit and are rounded for the eye: 18.8k in, 78% cached, 24 lines. Durations move up a unit as they grow: 45s, 1m05s, 1h02m; a finished tool call keeps a tenth of a second under a minute (2.4s).
  • Errors say what failed, then the one thing to try: ✗ Error: HTTP 401 above Check api_key or api_key_env…. Full output goes behind Ctrl+O, not into the conversation.
  • Keys are written as the keyboard labels them: Enter, Esc, Shift+Tab, Ctrl+O, ↑↓. Hints read Esc to interrupt or Tab or Enter selects, never "Press ESC to…".
  • No emoji anywhere in the terminal. Glyphs come from the set under Iconography.

Color

The dark theme is the product; the light theme is for light terminals, docs and screenshots in daylight. The TUI picks one per session ([ui] theme, else COLORFGBG).

Rules:

  • fin is never used for success and lagoon never for a warning. When in doubt, who is it waiting on? Human → fin. Killi → lagoon.
  • fg-faint is for marks the user can afford to miss (the gutter │, the rules around the prompt, the empty part of a meter). Any text that must be read is fg-muted or fg.
  • Success has no green of its own: a finished call is a lagoon ✓. Green, yellow and magenta exist only as syntax colors inside code blocks, where they mean nothing about state.
  • Solid fills (lagoon, fin as backgrounds) are for keycaps and mode badges on the web; the TUI has none.

Terminal colors

The TUI prints each role as the nearest 256-color shade of its token (dark / light), so every terminal shows the same thing: lagoon 80 / 30, fin 209 / 130, warn 221 / 136, danger 204 / 124, fg-faint 242 / 245, bg-selected 237 / 254 (the 256-color cube has no dark teal, so the tint is a neutral grey). fg-muted is SGR dim, which follows any foreground. NO_COLOR drops every color and keeps bold, dim and the glyphs. The role constants live in tui/text.rs.

Typography

One family, mono (JetBrains Mono, falling back to the platform monospace). In the terminal there is exactly one size; hierarchy comes from weight and color:

  • body — the whole UI. Regular, fg.
  • body-strong — tool names, your own messages, the selected choice, headings in Killi's text. Bold.
  • heading — section labels on the web: uppercase, bold, fg-muted, tracked 0.08em. The TUI writes them lowercase in fg-muted (tasks 2/5).
  • title — page titles in the docs.
  • key — keycaps on the web.
  • display — the wordmark on the cover and docs hero; never inside the terminal.
  • caption — web and docs metrics; a terminal uses body in fg-muted instead.

Set line height to one terminal row (row-1, 20px at 13px). Never letter-space body text. Never italicize UI text — many terminal fonts synthesize italics. The one exception is *emphasis* in Killi's Markdown, which keeps its meaning.

Layout & spacing

  • A status row is a glyph in column 0, a space, then its text in column 2 (✓ read src/lib.rs). Output under it hangs off a │ in fg-faint in column 2, its text in column 4.
  • Killi's prose and Markdown start in column 0 with no marker; list items wrap under their text, code blocks hang off ▏.
  • Blank rows do the separating, never two in a row: one before and after your message, one between a run of tool calls and the prose next to it, one before and after anything that is neither (a notice, an error, a question, /help, a /btw answer, Ctrl+O output). Consecutive notices stay together, and so do consecutive tool calls and the thought above them.
  • Width: prose wraps between words at the terminal width; status rows are cut with …, never wrapped. Tables shrink their widest column to fit.
  • The live area, bottom up: the status line, the prompt between two rules, the task list, then the rows of work in flight with the working spinner nearest the prompt. A blank row sits above the prompt's top rule and above the task list, so the conversation, the work and the prompt never touch. A picker or the choices of a question open under the prompt after a blank row too.

Borders & boxes

Prefer no box. The prompt sits between two full-width rules in fg-faint; in plan mode both turn lagoon and the top one carries the label:

── plan mode · Shift+Tab leaves it ─────────────
❯ add a --json flag to the export command
────────────────────────────────────────────────

Pickers open under the prompt with a lagoon title rule (── Switch model ────). Glyph set: ─ │ ┼ ▏. Never heavy (━ ┃, except the filled part of a meter) or double (═ ║) lines, never ASCII +--+. On the web, every border is stroke-hair and corners are radius-pane (panes) or radius-chip (chips); inside the terminal there are no corners.

States

A tool call is running in the live area, then done or failed in the scrollback, in the same column. Render the glyph in column 0, the tool's name in body-strong, its arguments in fg, then · result · time in fg-muted (time only from a second up). A failure puts its reason in danger and, for bash, shows the last lines of output under the gutter instead of the first.

Motion

Only four things move, on one 100ms tick: the wordmark sweep on the working row, the quarter glyph of each running tool call, the elapsed timers, and the stream of tokens as they arrive. No fades, no slides, no blinking. The terminal's own cursor marks where you type. On the web, prefers-reduced-motion holds every animation on its first frame.

Logo

assets/Logos/killi-mark.svg is the mark for the docs and icons: a prompt caret ❯ in lagoon with a cursor bar in fin. It never appears in the terminal. There the banner is the block-letter KILLI in its sky-to-violet gradient (tui/banner.rs), and the same gradient sweeps through the killi wordmark while Killi works.

Components

Nine families, each with a live preview and guidelines below: Banner, Prompt, Turn, ToolCall, TaskList, Question, StatusBar, Diff, Spinner. The React bundle (window.Killi) renders them for the web from the same glyphs, colors and spacing the TUI prints.

Spacing

The terminal grid is the scale: 1 cell ≈ 8px wide at 13px mono, 1 row = 20px. Web renderings use the px values; the TUI counts cells and rows.

cell-18px One character column. Gap between a glyph and its label; the inner padding of a keycap.
cell-216px Two columns. The gutter every block is indented by under its `❯` or `●` marker; horizontal padding of raised panes.
cell-324px Three columns. Between side-by-side metrics on the web; the TUI status line splits groups with ` │ `.
cell-432px Four columns. The widest gap used: between the two columns of the banner.
row-120px One terminal row. Vertical rhythm between lines inside a block; the height of every single-line control.
row-half10px Half a row. Vertical padding inside raised panes in web renderings only — a terminal uses a blank row (`row-1`) or nothing.
row-240px A blank row between turns and between a tool call and the prose that follows it.

Radius

A terminal has no corners. Radii exist for the docs site, the web playground and screenshots.

radius-none0px Everything inside the terminal. Corners come from box-drawing glyphs, not CSS.
radius-chip4px Keycaps, mode badges and status pills in web renderings.
radius-pane8px Raised panes in web renderings and the docs site.

Components

Banner

Shell

The first thing a session prints: KILLI in block letters with a sky-to-violet gradient, and beside it the name and version, the tagline, the model and the folder. Under it, in fg-muted: what the session loaded, a resumed session's last prompt, and the four keys a new user needs.

Provide: version, model, effort (left out for the provider's default), cwd (shortened with ~, cut from the left with …), notes.

  • Do move the side lines under the logo when the terminal is narrow, and drop the logo when even it does not fit.
  • Do keep the gradient to the logo and the working spinner; it is the one place Killi is decorative.
  • Don't use the SVG mark or the lagoon/fin pair in the banner.

Prompt

Shell

The composer: the lagoon caret ❯ and the typed text between two full-width rules in fg-faint. Known /commands and skills light up in lagoon as you type. The slash menu and pickers open under the bottom rule.

Provide: value, plan (turns both rules lagoon and labels the top one).

  • Do grow with the text up to ten rows, then scroll within them.
  • Do keep typing open while Killi works: Enter queues the message for its next step, shown above as a fin ❯ row.
  • Don't frame it in a box; the rules are the frame.

Turn

Conversation

Your message is a full-width band on the tint, a fin ❯ and the text in bold, with a blank row on each side, so you can find your own turns while scrolling back. Killi's reply is Markdown styled as it streams, in column 0 with no marker.

Provide: role (user or killi) and the body as children; <code> renders in lagoon. Thought renders a finished thought.

  • Do keep prose fg. Inline lagoon is for code, commands and links; h1–h2 are lagoon bold, smaller headings bold.
  • Do show a thought that took two seconds or more as one fg-muted row, ∴ Thought for 5s: and its first sentence; the full text is behind Ctrl+O.
  • Do end a turn that took a while with one fg-muted row: 1m06s · 6 requests · 18.8k in, 78% cached · 922 out.
  • Do print a /btw answer as one block: a bold fin btw and the question, the answer hung off the │ gutter, and a last muted row, Not kept in the conversation · 4.2k in, 92% cached. While it is answered it is a running row, ◐ btw question · 2s; if the model is mid-paragraph the block waits for the paragraph's end.
  • Don't put cards, bubbles or labels around Killi's prose.

ToolCall

Conversation

One tool call is one row: the status glyph, the tool's name in body-strong, its arguments, then · result · time in fg-muted. While it runs it lives in the live area with a turning ◐; when it ends it is printed to the scrollback as ✓ or ✗ in the same column.

Provide: name, args, status (running · done · failed), brief (24 lines, +9 −1, or the failure), duration, optional label for a subagent's call, output as children.

  • Do show up to three lines of a bash call's output under the │ gutter: the first when it passed, the last when it failed, then … n more lines · Ctrl+O.
  • Do show an edit's diff under the same gutter (see Diff).
  • Do mute a subagent's calls whole, after ↳ label: — only the glyph keeps its color.
  • Don't wrap a call's row; cut its arguments with ….

TaskList

Live area

The agent's todo list, above the prompt while any task is open: a fg-muted tasks 2/5 heading, then one row per task with its glyph — ✓ done (title muted), ◐ doing, ○ to do.

Provide: tasks (title, status: done · running · queued).

  • Do keep the plan's order; status never reorders it.
  • Do show at most eight rows, then … n more.
  • Don't keep it once every task is done.

Question

Waiting on you

When Killi needs you: a fin ? and the question in bold in the scrollback (or ? Plan and the plan, in plan mode), the numbered choices under the prompt, and the keys in fg-muted. Your answer is printed after a fin ↳.

Provide: question, options, selected, optional answer.

  • Do put the selected choice on the tint with a lagoon ❯ and its label in bold.
  • Do let a digit choose at once, and typing give your own answer instead.
  • Don't time it out: the turn waits, and a desktop notification says so.

StatusBar

Shell

The last row, in groups split by a fg-faint │: the model in fg, the effort in effort, the active mode in lagoon, the context meter with used/window, the session's tokens in tokens and the branch in branch. Labels (effort, ctx, in, cached, out) stay fg-muted; the figure carries the color.

Provide: model, effort, mode, context, window, input, cached, output, branch.

  • Do turn the meter and the context figures warn from 80 % of the window, and a dirty branch's *; those are the only signal colors this row uses.
  • Don't use effort, tokens or branch outside the status line and the banner's effort.
  • Do drop detail as the terminal narrows: the cache and token figures, the meter, the branch, and last the context figure — the model and mode stay at any width.
  • Don't put notices or errors here; they go in the conversation.

Diff

Conversation

An edit as Killi made it, under its ✓ edit row: behind the │ gutter, the line number in fg-muted, then the sign and the text — lagoon for an added line, danger for a removed one, fg-muted for context.

Provide: lines (kind: add · del · ctx, n, text).

  • Do show at most sixteen rows, then … n more lines.
  • Do cut long lines rather than wrap them; code keeps its columns.
  • Don't add line grounds in the terminal: 256 colors have no tint dark enough, so the sign and color carry the meaning.

Spinner

Signals

The working row, nearest the prompt while Killi works: the killi wordmark — its letters fade in, then the banner's gradient drifts through them under a sweeping highlight — followed by working 12s · Esc to interrupt in fg-muted. A running tool call turns the quarter glyph ◐ ◓ ◑ ◒ instead.

Provide: elapsed; Quarter for a tool row.

  • Do keep exactly one wordmark on screen; tool rows above it carry their own glyph.
  • Do hide the working row while a question waits on you — stillness means Killi is not working.
  • Don't animate the glyph of a finished call.

import type { ReactNode } from 'react';

/** A tool call is running in the live area, then done or failed in the scrollback. Tasks are queued, running or done. */
export type KilliStatus = 'queued' | 'running' | 'done' | 'failed';

export interface BannerProps {
  /** Semver without the v. */

  /** The model's alias, as the status line shows it. */

  /** Thinking effort; left out for the provider's default. */

}
export declare function Prompt(props: PromptProps): JSX.Element;

  /** A subagent's label: the row is muted after `↳ label:`. */

  /** Output rows behind the `│` gutter, already cut to three plus a `… n more lines` row. */
  children?: string;
}
export declare function ToolCall(props: ToolCallProps): JSX.Element;

export interface KilliTask {
  id?: string;
  title: string;
  status?: 'queued' | 'running' | 'done';
}
export declare function TaskList(props: { tasks: KilliTask[] }): JSX.Element;

  question?: string;

  plan?: boolean;
  options?: { label: string; note?: string }[];

  selected?: number;
  /** Once answered: the head and a fin `↳` row instead of the choices. */
  answer?: string;
}
export declare function Question(props: QuestionProps): JSX.Element;

export interface StatusBarProps {
  model: string;
  effort?: string;
  /** "plan" or "swarm", in lagoon. */

  context?: number;
  window?: number;
  /** Session tokens: fresh and cached input, output. */
  input?: number;
  cached?: number;
  output?: number;
  /** With `*` when the work tree is dirty; the `*` is warn. */
  branch?: string;
}
export declare function StatusBar(props: StatusBarProps): JSX.Element;
